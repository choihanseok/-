## 목적
공통 Order와 서비스 제공자를 연결하는 Matching 공통모듈의 최소 기반을 추가한다. 특정 서비스명에 종속되지 않고 향후 DRIVING/QUICK/FLOWER/ERRAND 및 추가 Service Module이 재사용할 수 있어야 한다.

## 구현 범위
- MatchingStatus 코드 정의
- Matching Entity / Repository 계약
- SQLite reference repository 및 migration
- Order ↔ Provider 배정
- 배정/재배정 이력 보존
- Provider 승인/거절
- 기존 Role + Permission + Scope + Ownership 연동
- Order 상태와 Matching 상태의 최소 동기화
- 정상/잘못된 요청/권한 없음/중복 요청/거절/재배정/DB 제약/회귀 테스트

## 제외
- 거리/평점/가격 기반 자동매칭 알고리즘
- 외부 자동콜패스
- Payment / Settlement
- 서비스별 상세 Matching 정책
- 운영용 DBMS/ORM 확정

## 안전 원칙
- 기존 파일/API/테이블/데이터 삭제 금지
- 기존 Order 계약의 파괴적 변경 금지
- Matching 이력은 삭제/덮어쓰기하지 않고 추가 기록
- 권한은 Backend Service에서 검사
- 정책 미확정 항목은 NEED_REVIEW

## NEED_REVIEW
- 자동매칭 우선순위 및 점수식
- Provider 가용성/근무상태와 ProviderStatus의 최종 관계
- 동시 다중 배정 허용 여부
- Provider 거절 사유 코드 Master
- 재배정 최대 횟수/타임아웃
- 운영 DBMS/ORM/트랜잭션 격리 수준
