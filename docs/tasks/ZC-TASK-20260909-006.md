# ZC-TASK-20260909-006 — Service Registry Foundation

## Status
READY

## Objective
ZERO CALL의 서비스 확장 구조를 코드와 DB에 연결할 준비를 완료한다.

이번 Task의 핵심은 서비스명을 코드에 하드코딩하지 않고 `serviceId / serviceCode / serviceName / serviceType / status / configuration` 기반 Service Registry를 공통모듈로 구현할 수 있게 개발 범위를 고정하는 것이다.

## Source / Project Basis
ZERO CALL Master Rule 기준:
- 공통 플랫폼 + 공통모듈 + 서비스별 모듈 구조
- 새로운 서비스는 `serviceCode`, `serviceType`, `serviceConfig`로 구분
- 특정 서비스명을 조건문에 직접 고정하지 않음
- Phase 1 서비스: DRIVING, QUICK, FLOWER, ERRAND
- 서비스 개념모델: MBS, EST, RNT, BUY, AUC, MTC, INF, AGC
- Role/Permission은 Backend/API에서 검사

## Repository Contract
Required operations:
- findById(serviceId)
- findByCode(serviceCode)
- list({status, serviceType})
- save(service)
- saveConfig(serviceId, key, value)
- getConfig(serviceId, key)

Duplicate `serviceCode` must be rejected.

## Service Layer
`ServiceRegistryService` responsibilities:
- registerService
- getService
- getServiceByCode
- listServices
- changeStatus
- setConfiguration
- getConfiguration

Must not contain service-specific business logic.

Forbidden examples:
```js
if (serviceCode === 'DRIVING') { ... }
if (serviceName === '대리운전') { ... }
```

Allowed pattern:
```js
service.serviceType
service.serviceCode
service.configuration
```

## Authorization
Reuse current `AuthorizationService`.

Foundation permission codes:
- SERVICE.VIEW
- SERVICE.CREATE
- SERVICE.UPDATE
- SERVICE.MANAGE_CONFIG
- SERVICE.CHANGE_STATUS

Recommended boundaries:
- CUSTOMER / PROVIDER / MERCHANT: VIEW only when explicitly granted
- SERVICE_ADMIN: SERVICE scope
- DISTRIBUTOR: DISTRIBUTOR or explicitly granted service read scope only
- PLATFORM_ADMIN: PLATFORM scope
- SUPER_ADMIN: SYSTEM scope

No Role automatically bypasses the permission engine.
