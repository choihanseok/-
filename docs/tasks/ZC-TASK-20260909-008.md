## State Transition Foundation
Foundation transition rules are explicitly coded.
Terminal states COMPLETED / CANCELLED / FAILED do not transition further in this Task.
Repeated transition to the current status is idempotent and does not append duplicate history.

Final business transition policy remains subject to the confirmed Status Master and service policy review.

## Service Registry Integration
Order creation resolves a registered service using serviceId/serviceCode.
- missing service -> ORDER_SERVICE_NOT_FOUND
- serviceId/serviceCode mismatch -> ORDER_SERVICE_MISMATCH

No service-specific business branches such as `if DRIVING` or `if QUICK` were added.

## Location Integration
Order does not duplicate origin/destination/waypoint columns.
Existing common Location records are linked with:
- referenceType = ORDER
- referenceId = orderId

`OrderService.listOrderLocations()` returns common Location records after Order authorization.

## Authorization
Permission codes:
- ORDER.VIEW
- ORDER.CREATE
- ORDER.CHANGE_STATUS
- ORDER.ASSIGN

The existing AuthorizationService is reused.
Authorization is deny-by-default.
Tests cover:
- CUSTOMER SELF create/view
- another CUSTOMER cannot view someone else's order
- SERVICE_ADMIN service scope cannot cross another service
- provider assignment requires explicit ASSIGN permission

No UI-only permission check was introduced.
